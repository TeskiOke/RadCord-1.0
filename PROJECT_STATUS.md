## 🐛 Баги — Исправлено в этой сессии

### БАГ 1 — КРИТИЧЕСКИЙ: Дублирующий метод `_on_voice_state` перезаписывал рабочий
**Файл:** `ui/app.py`  
**Суть:** В классе `MainWindow` был определён **второй** метод `_on_voice_state(self)` без аргументов (строка ~610), который **полностью перекрывал** рабочий `_on_voice_state(self, device_id, in_voice, speaking)` (строка ~508). Python всегда вызывал заглушку. Результат: сигнал `voice_state_changed` приходил, но ничего не происходило — ни грид не обновлялся, ни сайдбар.  
**Статус:** ✅ Исправлено. Заглушка удалена.

---

### БАГ 2 — КРИТИЧЕСКИЙ: Аудио-стримы не запускались при старте
**Файл:** `ui/app.py`  
**Суть:** `AudioManager.start_streams()` вызывался **только** при сохранении настроек (`SettingsDialog`). При обычном запуске приложения sounddevice-потоки никогда не открывались — `_running = False`. `_capture_loop` немедленно завершался при вызове `start_capture_task()`. Микрофон и воспроизведение аудио не работали до первого открытия настроек.  
**Статус:** ✅ Исправлено. `start_streams()` теперь вызывается в `__init__` MainWindow сразу после настройки колбэков.

---

### БАГ 3 — КРИТИЧЕСКИЙ: Пиры добавлялись в Voice Grid при подключении, а не при входе в голос
**Файл:** `ui/app.py`  
**Суть:** `_on_peer_joined` вызывал `self._voice_grid.add_peer(info)` для каждого нового пира — сразу при подключении, вне зависимости от того, зашёл ли он в голосовой канал. Это ломало логику: в голосовом гриде оказывались все онлайн-пиры.  
**Статус:** ✅ Исправлено. Пир добавляется в грид только через `_on_voice_state` когда `in_voice=True`.

---

### БАГ 4 — Смена сети не очищала Voice Grid
**Файл:** `ui/app.py`  
**Суть:** `_select_network` удалял из грида только **себя** (`remove_peer(self_device_id)`), но карточки других пиров оставались висеть после переключения сети.  
**Статус:** ✅ Исправлено. Теперь полностью очищаются все карточки перед перестройкой состояния.

---

### БАГ 5 — `_on_voice_state` не управлял гридом при выходе из голоса
**Файл:** `ui/app.py`  
**Суть:** Когда пир уходил из голосового канала (`voice_leave`), его карточка в Voice Grid не удалялась. Метод только вызывал `update_voice()`, но не `remove_peer()`.  
**Статус:** ✅ Исправлено. При `in_voice=False` теперь вызывается `voice_grid.remove_peer()`.

---

### БАГ 6 — `AttributeError` в `VoicePeerCard.set_speaking()`
**Файл:** `ui/voice_grid.py`  
**Суть:** Метод `set_speaking()` обращался к `self._is_muted` и `self._is_speaking`, но они инициализировались только при первом вызове `set_muted()` / `set_speaking()`. При определённом порядке вызовов (например, `set_speaking` до `set_muted`) — `AttributeError`.  
**Статус:** ✅ Исправлено. Обе переменные теперь инициализируются в `__init__`.

---

### БАГ 7 — `set_speaking`, `voice_state` и аудио рассылались без `network_id`
**Файл:** `ui/app.py`  
**Суть:** Вызовы `mesh.set_speaking()`, `mesh.broadcast_audio_to_voice()` и `broadcast_json({type: voice_state})` шли без указания `network_id`. По логике `broadcast_json`, если `network_id` не указан — сообщение уходило всем пирам, независимо от их сети. Кроме того, `mesh.set_speaking()` требует `network_id` обязательно — без него падал `TypeError`.  
**Статус:** ✅ Исправлено. Все вызовы теперь передают `self._voice_net_id`.

---

### БАГ 8 — `Set` не был импортирован в `audio.py`
**Файл:** `core/audio.py`  
**Суть:** Аннотация `_local_mutes: Set[str]` использовала тип `Set` из `typing`, который не был импортирован. На Python < 3.10 в режиме «ранних аннотаций» это вызывает `NameError`.  
**Статус:** ✅ Исправлено. `Set` добавлен в импорт `from typing import ...`.

## 🔴 Известные ограничения (архитектурные)

| # | Ограничение | Детали |
|---|-------------|--------|
| 1 | **Только Radmin VPN / LAN** | Прямые P2P-соединения. Нет STUN/TURN, NAT traversal отсутствует. |
| 2 | **Нет шифрования** | Аудио и текст идут по WebSocket без TLS. Для работы в доверенной сети (Radmin) приемлемо. |
| 3 | **Один голосовой канал одновременно** | Нельзя быть в двух голосовых каналах. Архитектурно `_voice_net_id` — одна переменная. |
| 4 | **Аудио-кодек — сырой PCM** | Нет Opus/AAC. Передаётся `int16` PCM 16kHz. Большой поток при плохом канале. |
| 5 | **Нет переподключения** | При разрыве соединения пир удаляется. Автопереподключение — только через discovery (до 5 сек). |
| 6 | **Один порт WS (8765)** | Нельзя запустить два экземпляра RadCord на одной машине (порт занят). |
